# 実機負荷試験: 10,000ノート（AT-11 / AT-12）

## 目的

ローカル索引が大規模Vaultで使えるかを実アプリで測る。RV-01（大規模VaultでのUI停止）の判定に使う。

## 方法

- Vault: `scripts/gen-corpus.mjs --notes=10000` の決定的な合成Vault（seed 20260919）
- Obsidian 1.13.7 を新規プロファイルで起動し、`community-plugins.json` に `jev-search` を書いて**起動時に**ロードさせる
- 索引は `onLayoutReady` から始まるので、`layoutReady` から `plugin.indexed` が真になるまでを計測
- 同時に `PerformanceObserver`（longtask）と `requestAnimationFrame` の間隔を記録
- 各条件2〜3回実行し中央値で比較

`app.plugins.enablePlugin()` は**新規プロファイルでは効かない**（プラグインがロードされないことを実測で確認）。そのため起動時ロードに切り替えた。

## 結果

### 索引時間

| 条件 | 実行1 | 実行2 | 実行3 | 中央値 |
|---|---|---|---|---|
| 1ノートごとにyield（変更前） | 51,591ms | 52,531ms | — | **52.1s** |
| 8msの時間予算でyield（変更後） | 16,261ms | 16,387ms | 16,864ms | **16.4s** |

**3.2倍高速。** 条件内のばらつきは小さく（変更前 ±1.8%、変更後 ±3.7%）、差はばらつきを大きく超える。

参考: 変更前の初回実行は74,835msだった。OSのファイルキャッシュが冷えていた影響と考え、比較には上の統制された2回を使う。

### UIの応答性

| 指標 | 変更前 | 変更後 |
|---|---|---|
| フレーム間隔 p95 | 17〜18ms | 20〜23ms |
| フレーム間隔 最大 | 224〜256ms | 231〜282ms |
| 200ms超のフレーム | 2 | 2 |
| longtask 最大 | 224〜256ms | 231〜273ms |
| JSヒープ | 144MB | 189〜251MB |

- **UIは停止しない。** p95は60fps（16.7ms）に近く、200msを超えたフレームは全実行で2回だけだった。
- 変更後はyieldの頻度が下がるためp95が17→21ms程度に悪化する。体感できる停止ではないが、**速度と引き換えのトレードオフ**である。
- ヒープはV8の上限4,192MBに対して十分小さい。

### 検索の応答（索引完了後）

| クエリ | 時間 | 件数 |
|---|---|---|
| 定例会 | 0.2〜0.3ms | 0 |
| 経費精算の締め日 | 0.2〜1.5ms | 8〜50 |
| VPN | 0.1〜0.4ms | 3〜50 |
| デプロイ | 2.3〜2.5ms | 50 |
| 存在しない語句ZZZ | 3.5〜17.4ms | 50 |

件数は索引の進行状態で変わる。`定例会` はこの合成Vaultに存在しないので0件が正しい。

## 見つかった不具合: 「Ready」が索引完了前に立つ

計測中、`indexed` が真になった時点で**6,400件しか索引されていない**実行があった。

原因: `allowed()` は `metadataCache.getFileCache()` を要求する。起動直後はObsidianのメタデータ走査が終わっておらず、`null` が返るノートは**黙って飛ばされる**。飛ばされたノートは後で `metadataCache` の `changed` で拾われるが、その前に `rebuild()` のキューが空になり「Ready」と表示される。

**索引の高速化がこの不具合を露出させた。** 変更前は索引に52秒かかり、その間にメタデータ走査が終わっていたため目立たなかった。

修正: メタデータ未解決が理由で飛ばしたノートを `pending` に記録し、キューが空になった後も `pending` が空になるまで再試行してから `indexed` を立てる（250ms間隔・最大80回＝20秒）。

修正後は**全実行で「Ready」時点の索引数が10,000件**になった。

## 限界

- 合成Vaultであり、実Vaultのノート長・リンク密度・タグ分布とは異なる。
- メタデータ走査との競合はタイミング依存で、実行ごとに完全には統制できていない。
- Obsidian 1.13.7 と Windows に依存する。
- ヒープの比較にはObsidian自身のキャッシュが混ざるため、プラグイン単体の使用量ではない。
- 50ノート未満の小規模Vaultでは、この差は体感できない。

## 再現

```
node scripts/gen-corpus.mjs --out=.sandbox/load-vault --notes=10000 --clean
npm run build
node scripts/load-test.mjs --vault=.sandbox/load-vault --profile=.sandbox/load-profile
```
