# 03. ローカル検索と再ランキング

## インデックス構築

NoteSourceはObsidian Vault APIでMarkdownのみ列挙。OSの再帰走査やリンク先ファイル読取りは行わない。
configDir（.obsidianに固定しない）・ドットディレクトリ・利用者除外を先に適用。
タグはMetadataCacheのfrontmatter/本文タグを統合。メタデータ未確定のノートは索引投入を保留。

起動後遅延構築。create/modify/delete/renameとmetadata changedを登録・無効化時解除。
変更イベントを300ms debounceして当該ノートだけ削除→再登録。設定の除外変更時は
policyGenerationを増やし該当チャンクを即除去、再索引する。全ノート再構築を毎検索で行わない。
読み取り前後のmtime/sizeを照合し、変化したデータは再読込待ちにする。
検索結果はindexGenerationに紐付け、更新中は「一部索引更新中」と表示する。

## Markdown・文字処理

- ATX見出し1〜6を境界とする。コードフェンス内の#は見出しにしない。
- frontmatterはObsidianの解析位置を利用し送信から除外。独自の汎用YAML解析器は作らない。
- コード/リンクは文字として検索し、画像・埋込み先は展開しない。
- 各チャンク最大1,200 Unicode code point。段落優先、長段落は1,200/overlap120で分割。
- 見出しがなくても先頭本文を保持。巨大1MiB超ノートは索引対象外として明示。
- ID = vault内path + startLine + fragment ordinal + content hash。見出しの重複でも一意。
- 原文の行番号と本文は保持。正規化は検索用だけで、クリック時の位置を壊さない。

トークン化はNFKC、小文字化、Unicode code point走査。
ASCII英数字/underscoreは単語単位。日本語の漢字/ひらがな/カタカナ/長音の連続区間はbigram。
1文字区間はunigram。ASCIIに文字bigramは作らない。
例: `BM25 管理` → `bm25, 管理`。`再ランキング` → `再ラ, ラン, ンキ, キン, ング`。
これは形態素解析でも意味理解でもない。単語同義語・表記ゆれのRecall不足は評価で測る。

## BM25と候補選択

フィールドごと(title/heading/body)にdf、tf、avgdlを保持する転置索引。
IDF = ln(1 + (N-df+0.5)/(df+0.5))。
BM25 = Σ IDF × tf(k1+1)/(tf+k1(1-b+b×dl/avgdl))、k1=1.2、b=0.75。
最終値 = 3×title + 1.5×heading + body。クエリ語は重複除去。
空索引/空クエリは0件。全文一致ゼロなら勝手に外部検索しない。

上位50チャンクを取得し、ノート最大2チャンク、最大20ノートまでを再評価候補にする。
ノートのローカル順位は最大チャンクスコア。スコア同点はpath・行番号で安定ソート。
候補上限によって欠落する正解はJevで救えないためRecall@50を最初に検査。

## 外部送信用候補

query最大512 code point、title/heading各128、textはチャンク内最大1,200。
候補選定後に02の24KiB上限でバッチ化。1操作最大2バッチ、1送信20候補。
切り詰め/未送信はプレビューに表示。過大な単一候補は送らず未評価。
スナップショットの本文を承認後に読み直して差し替えない。

3段階Score: 0=無関係、1=同じ話題、2=直接回答を含む。
暫定ラベル境界は1.0/1.5。ただし1.5は「正答率75%」ではない。
低スコアを自動削除しない。初版にはkeepAtによる自動プルーニングを搭載しない。

## 結果統合

- 成功した同一バッチ内のみスコア降順で並べ替え、同点はローカル順位。
- 複数バッチは元の候補スロットにバッチ内順位を戻す。バッチ間のスコア較正を仮定しない。
- 未送信/無効バッチは元のスロットを保つ。「未評価」を表示。
- ノート代表は最大スコアの評価済みチャンク、根拠抜粋を併記する。
  表示は重複ノートをまとめるが元のローカルタブの順序と全候補は保存。
- 全スコアが1.0未満なら「回答候補を確認できず」と表示し元順へ戻す。
- 全失敗はfallback、一部成功はpartial、全成功はreranked。

## 状態機械

idle → indexing/localSearching → localReady → preview → sending → reranked/fallback/partial。
検索文字列変更は即queryId更新、local searchは150ms debounce、IME変換中は待機。
再ランキングはボタン操作だけ。入力ごとの自動API呼出しは禁止。
プレビュー中のquery/index/policy/credential変更は承認無効化。
送信直前と適用直前に世代を照合。結果が遅着しても新しい検索を上書きしない。
ノート削除/改名後のリンクは再解決し、不明なら「位置が変わりました」と案内。
