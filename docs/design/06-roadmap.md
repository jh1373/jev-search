# 06. 段階計画・ADR・リスク

現状は設計段階。工期はG0で難所を計測してから見積もる。全実装済みとは扱わない。

## ゲートと実装順

| Gate | 成果物 | 完了基準/停止条件 |
|---|---|---|
| G0 接続スパイク | 最小Plugin、合成ノート、ビルド、Transport/秘密保存の検証記録 | 実Obsidian読込・合成1問応答。redirect/取消/保存先が安全に扱えなければ方式再設計 |
| G1 ローカル検索 | tokenizer/chunker/index/policy/UI | オフライン、増分、除外、10kノート負荷試験。Recall不足なら候補検索改善が先 |
| G2 Jev連携 | 同意、payload、validator、cache、比較UI | 全セキュリティ受入テスト通過、失敗時ローカル維持 |
| G3 品質検証 | 公開日本語コーパス、held-out結果 | 改善の証拠なしなら「高精度」を宣伝しない。需要/性能次第でJev機能を実験扱いに留める |
| G4 配布ベータ | 3OS試験、非開発者5名程度の導入観察 | 支援なし初回検索4/5以上を暫定目標、重要不具合0 |
| G5 公開 | Release、ライセンス、プライバシー、申請 | 再現可能buildと07全項目、公開先の所有確認 |

担当は開発者/AIが実装・検査、ユーザーが秘密情報のローカル登録・配布アカウント操作。
実API呼出しはユーザーがテスト可能と表明しているが、秘密が未設定なら停止して未実施と報告。
APIキーをチャットで要求しない。GitHubへの公開は完成物レビューと所有者アカウントの準備後。

## ADR（0.2で更新）

- ADR-001 BYOK: 開発者キーの組込/代理課金サーバーなし。初回摩擦より費用責任の分離。
- ADR-002 ネイティブUI: CLI方式をそのまま移植しない。Obsidian内だけで使える構成。
- ADR-003 明示オプトイン: キー存在と同意を別管理。初版プレビューは毎回必須。
- ADR-004 最小依存: 自作万能主義を避け、導入時はライセンス/サイズ/更新状況を審査。
- ADR-005 BM25先行: 小さく開始。ただし意味検索とは宣伝せずRecallを先に測る。
- ADR-006 Score3段階: relevance評価に使用。confidenceは正答率として表示しない。
- ADR-007 削除なし: 未評価/低関連を誤って消さないため初版は並べ替えのみ。
- ADR-008 固定モデル: 応答版を照合しキャッシュに含める。無断latest移行なし。
- ADR-009 セッションキー: 未検証の平文永続化を避ける。保存機能はG0検証後。
- ADR-010 評価先行: 小規模pilotをG0/G1で実行、大規模UI構築前に価値の兆候を確認。
- ADR-011 Gateway優先: 開発と配布の第一経路はVercel AI Gateway(`ai-gateway.vercel.sh/v4/ai/evaluation-model`)、
  TypeSafe直接(`api.typesafe.ai/v1/systemone`)を第2経路として残す。理由: 開発者がTypeSafe直接キーを
  まだ持てない(待機リスト中)ため、GatewayでG0〜G3を実測できる。BYOK(ADR-001)は不変で、開発者キーは埋め込まない。
  制約: Gateway応答には解決済みモデル版が無いためADR-008の「応答版の照合」はGatewayでは成立しない。
  版固定は直接経路でのみ検証可能。Gateway経路は実験扱いとし、`ai-evaluation-model-specification-version: 4`
  と `only: ['typesafe-ai']` を固定し、警告が1件でもあれば不採用・ローカル維持とする。
  将来Gatewayが版露出を始めたら検証を有効化する。公開時の既定はユーザーの利用実態とZDR/料金を比較して
  G4で再判断する（無断で「TypeSafe公式と同等」とは宣伝しない）。
- ADR-012 OpenRouterを第一経路に: 開発・検証の第一経路をOpenRouter(`https://openrouter.ai/api/alpha/decisions`)へ変更し、
  TypeSafe直接(`api.typesafe.ai/v1/systemone`)を第2経路、Vercel AI Gatewayを第3経路へ下げる。
  一般ユーザーへの提供は OpenRouter と TypeSafe直接 の2経路とする。理由: (1) 応答に解決済みモデル版が含まれ
  ADR-008の版照合が成立する（Gatewayでは不可能だった）、(2) `usage.cost` で実コストを取得できる、
  (3) `provider.only:['typesafe']` + `allow_fallbacks:false` で他プロバイダへのフォールバックを禁止でき、
  (4) `zdr:true` + `data_collection:'deny'` を要求でき、TypeSafeはOpenRouterのZDRエンドポイント一覧に登録済み、
  (5) 価格は $0.042/MTok で直接経路と同額（マークアップなし）。
  制約: 契約は `/api/alpha/decisions` であり実験的である。OpenAPI仕様は公開されているが版が予告なく変わり得るため、
  契約版を固定してcanaryで検出し、失敗時はローカル維持とする。OpenRouterはプロンプトが経由する第三者であるため、
  同意ダイアログとREADMEに明示する。BYOK(ADR-001)は不変で、開発者キーは埋め込まない。
- ADR-013 SecretStorageでキーを保持: キーは「セッション上書き」→「Obsidian SecretStorage」の順で解決する。
  `data.json` には秘密の**名前**だけを入れ、値は入れない。理由: セッションメモリのみではObsidianを起動するたびに
  再入力が必要で、レビュー課題RV-04（保存UIなし）が未解決のまま残る。公式ガイドが SecretStorage を
  「`data.json` に平文で置く問題の解決策」として案内しており、`obsidian@1.13.1` の公開型に存在する
  (`@since 1.11.4`、`minAppVersion` は1.13.0なので常に利用可能)。設計書04が「G0で公式型/実機を確認して
  保存オプションを実装するか決める」としていた宿題であり、型の確認が済んだため実装する。
  制約: 保存先の実体・同期範囲・隔離は未確認のため、暗号化や非同期を宣伝しない。値が `data.json` に
  到達しないことは `npm run test:bundle` が検査する。非対応環境ではセッション入力のみへ戻し、平文へ無断フォールバックしない。

- ADR-014 カタカナ語を1語として索引: `tokenize` は日本語ランのbigramに加えて、
  カタカナ連続（2文字以上）を `w:` 接頭辞付きの1トークンとしても出力する。
  理由: bigram分割はカタカナ借用語の語の同一性を失う。`デプロイ` は `デプ / プロ / ロイ` になり、
  `プロ` は `プロジェクト` `プログラマー` にも現れるためIDFが崩れ、無関係なノートに当たる。
  実測（合成10,000ノート・48問）: literal の Recall@50 91.7%→95.8%、literal の MRR 0.889→0.931、
  全体 MRR 0.574→0.595。`デプロイはいつできる` は圏外（実順位85位）から1位になった。
  制約: 全体 Recall@50 の改善は+2.0ポイント（48問中1問）で、400ノートでは0。統計的な改善の証拠とは扱わない。
  `matchedAnywhere` は不変（87.5%）で、これは一致ではなく順位の問題だったことを示す。
  実文書での再測定まで「検索精度が上がった」と宣伝しない。
  計測記録は [result-synthetic-recall.md](../benchmark/result-synthetic-recall.md)。

- ADR-015 索引のyieldを時間予算にする: 索引は1ノートごとにイベントループへ戻していたが、
  8msの時間予算に変えた。理由: 1ノートごとのタイマーは、それが保護する索引処理より高くつく。
  実測（実Obsidian・合成10,000ノート、各条件2〜3回の中央値）: 52.1s → 16.4s（3.2倍）。
  UIは停止しない（フレーム間隔p95 17〜18ms → 20〜23ms、200ms超のフレームは前後とも2回）。
  引き換えにp95が数ms悪化する。計測記録は [result-load-10k.md](../benchmark/result-load-10k.md)。
- ADR-016 「Ready」は索引完了後に立てる: `allowed()` は `metadataCache` を要求するため、
  起動直後にメタデータ未解決のノートが黙って飛ばされ、10,000件中6,400件で「Ready」になる実行があった。
  メタデータ未解決で飛ばしたノートを `pending` に記録し、空になるまで再試行してから
  `indexed` を立てる（250ms間隔・最大20秒）。修正後は全実行で10,000件で「Ready」になる。
  索引の高速化（ADR-015）がこの不具合を露出させた。

## リスク登録簿

確率は根拠がないため全て未評価。検出指標と行動を定義する。

| リスク | 検出指標 | 対応・停止条件 |
|---|---|---|
| 語彙検索で候補欠落 | Recall@50、同義語層の失敗 | rerankに投資する前にトークナイザ/候補生成改善 |
| 日本語で改善しない | held-out nDCG差・CI | 主張を縮小、Noul比較/候補検索改善、機能実験扱い |
| 誤送信 | 未承認payload、除外すり抜け | 即出荷停止、同意state machine再検証 |
| キー漏洩 | secret scan/診断検査 | 失効案内・修正・再発防止 |
| API価格/版/上限変更 | 401/422/429/usage変化 | ローカルへ、設定で明示移行、料金説明を更新 |
| Transport取消不能 | deadline後の未完了Promise | 物理枠保持・追送しない。cancel文言を正確化 |
| 大規模VaultでUI停止 | p95/long task/heap | 増分・yield・対応規模明示、必要ならworker検討 |
| 非開発者が導入できない | ベータ導入完了率 | onboarding改善、安全なキー保存を優先 |
| ライセンス/審査問題 | releaseチェック | 流用保留、該当依存除去、申請条件を再確認 |

## 参照コードと公開方針

metalmind、jev-rerank、typesafe-mcp、Hybrid Searchは概念参照。
ライセンス名をREADMEだけで推測しない。直接流用時は対象commitとLICENSE/NOTICEを確認し、
著作権表示と変更点を記録。Apache-2.0由来を無条件にMITへ再ライセンスしない。
本製品のライセンスはMITを提案。著作権者名は公開前にユーザーに確認する。
Git初期化/署名/公開名を勝手に偽造しない。main保護・PR・独立レビューを運用目標とする。
